Your site already has an API. It's just written in buttons.

An agent pointed at your product today squints at pixels, guesses which div is the submit button, and hopes. WebMCP flips it: the page hands the agent a typed list of things it can actually do. Same JavaScript you already shipped — now with a name, a description and a schema.

Before — the agent guesses
screenshot() → 1.2 MB find “Refund” … 3 candidates click(x=812, y=447) ✕ modal moved. retry 2/5

Vision-driven flows land somewhere near half the time, and every layout tweak breaks them again.

After — the site declares
tools() → 7 declared issue_refund · destructive { ticket: "T-1042", cents: 14800 } ✓ browser asked the human first

Structured in, structured out, consent mediated by the browser instead of by luck.

The sixty-second version

Three moves. That's the whole protocol surface you need to be useful to an agent.
